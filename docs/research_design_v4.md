# 研究設計 v4 — 進化的社会学習（事前登録文書）

作成: 2026-09-29。**結果を見る前に固定する**（主要評価・検定・問題集合・中止規則）。
変更する場合は理由と日時を末尾の変更履歴に残す。

## 0. 位置づけ

2026-07 の v1〜v3 は、次の3点により「チーム貢献度による進化」を検証できる状態になかった。
- 初期集団に遺伝的多様性がなかった
- 適応度がノイズに支配されていた
- 議論が同調に支配されていた（自己回答を提示していなかった）

加えて、採点器に2つの欠陥が見つかった（MMLU-Pro の偽 'A'、MATH の約6.5%の偽陰性）（`docs/review_2026-09/`）。
v4 はテーマ「性格の異なるペルソナ LoRA が対話し、社会が世代を重ねて進化して精度が上がる」を保ち、
学習信号を持つ**文化的進化**として再設計する。

- 個体は、社会の対話のうち正解に至った発話から学ぶ（ラマルク的継承）。
- 社会はチーム貢献度（厳密 Shapley 値）で次世代の代表を選ぶ（ダーウィン的選抜）。

## 1. 研究課題

- **RQ1（進化の効果）**: 進化的社会学習を重ねると、社会（3ペルソナの議論チーム）の未見問題での精度は世代0より上がるか。
- **RQ2（選抜の効果）**: チーム貢献度（Shapley）による選抜は、選抜なしの社会学習より高い精度をもたらすか。
- **RQ3（適応度の水準）**: チーム貢献度による選抜は、個体の単独精度による選抜（A1）より優れるか。
- **RQ4（位置づけ）**: 最終世代の社会は、ベースモデル単体および計算量を考慮した Self-Consistency（SC@k）に対してどこに位置するか。

## 2. 手法（1 世代）

親 = 世代 t−1 の代表チーム（役割 critic / pragmatist / explorer）。

1. **議論**: 学習用問題 train_g{t−1}（1,200 問）で、親チームが round0（独立回答）と round1（自分の前回解答を会話履歴に保持し、他2体の解答を見て更新）を行う。
2. **学習データ**: 役割ごとに作る。
   - a（自己学習）: 自分の正解 round0 と、正解 round1。
   - b（社会学習）: a ＋、自分が誤り他者が正解した問題での他者の正解 round0。自分のペルソナのプロンプトで学ぶ。
   - 完了（stop）した発話のみを使い、上限 1,000 例をランダムに抽出する。
3. **学習**: 親アダプタから継続学習する（世代1は新規 LoRA）。条件は rank 16、α 32、bf16、1 エポック、1 ステップ約 3.3 万ラベルトークン（約 30 ステップ）、最後の assistant 発話のみに損失、lr は世代1が 1e-4・以降 5e-5。
4. **兄弟交叉**: c = ΔW 空間で a と b を平均し、rank 16 に SVD で再分解する。
5. **選抜**: 候補 {親, a, b, c} から役割ごとに選ぶ。親チームの文脈で全7連合を dev で実測し、特性関数 v(S) = dev のベンチマーク等重み（macro）精度とする。各候補の厳密 Shapley 値が最大の候補を次の代表にする。Banzhaf 値も同じ7連合から記録する。
6. **評価**: 新しい代表チームを test で評価する。

議論プロトコル（round1 の指示文）は、パイロットの dev 比較で決める（§6 の規則）。集約は round1 回答の多数決とし、同数は logprob 確信度が高い回答、なお同じなら役割名順（乱数は使わない）。

## 3. 比較条件（系統）

| 系統 | 選抜 | 目的 |
|---|---|---|
| **S（主）** | Shapley（候補 {親,a,b,c}） | 提案手法 |
| N（対照） | なし（常に b） | RQ2: 選抜の効果 |
| A1（対照） | 単独精度（候補 {親,a,b,c}） | RQ3: 適応度の水準 |
| RFT（対照） | ― | ペルソナ・議論なしの単一モデル自己学習（同じ学習用問題）。「単に自己学習したのと同じでは？」への対照 |
| 基準 | ― | 世代0の社会、ベース単体、SC@k（k=1..9） |

- 世代1の子（a,b,c）は全系統で共有する（同じ親・同じデータ）。系統が分岐するのは世代2以降。
- 世代数 G は S で 3（予算に余裕があれば 4）、N と A1 で 3。

## 5. 主要評価と検定（事前登録）

- **主要指標**: test のベンチマーク等重み（macro）精度。副次指標は問題数加重（micro）とベンチ別。
- **主要比較**（Holm 補正で FWER 5%）:
  1. H1: S の最終世代チーム ＞ 世代0の社会（RQ1）
  2. H2: S の最終世代 ＞ N の最終世代（RQ2）
  3. H3: S の最終世代 ＞ A1 の最終世代（RQ3）
- **検定**: 問題 ID をクラスタとした符号反転置換検定（両側、20,000 回）。区間はクラスタブートストラップ 95%CI（10,000 回）。macro 指標はベンチごとの差を等重み平均し、ベンチ内で問題を再抽出する。
- **生成 seed**: 主要比較のチームは test を生成 seed 2 本（g1, g2）で評価する。問題ごとに平均を取ってから検定する。
- **同等性**: 主張する場合のマージンは ±2pt、90%CI で判定（事前に固定）。
- **副次（探索的）**: 世代ごとの推移、SC@k 曲線上の位置（生成回数・出力トークンで揃えた比較）、議論の正誤遷移（同調率）、ペルソナ間の多様性（不一致率・oracle@3）、Shapley と単独精度の順位相関。

## 6. パイロットで決める設計値（dev のみを使う。test は見ない）

dev（400問）は、ベンチ別に層化して固定 seed（20260930）で A（選抜用 200）と B（確認用 200）に分ける。

- **議論プロトコル**（2026-09-30 改訂。第2パイロットの実行前に固定）:
  - 全文版の round1（自分と他者の回答をすべて提示）は、入力が平均 7.6K トークンになる。A100 40GB の KV キャッシュには同時に約20本しか載らず、出力が約500 tok/s に落ちる。この単価では進化の選抜（1世代で round1 約2.5万回）が予算に収まらないことが、第1パイロットで判明した。
  - そこで、**自分と他者の回答を末尾 3,000 文字に切り詰めた v4t（中立指示）と v4ct（条件付き指示）を採用候補**とする。dev-A の macro 精度が高い方を採用し、v4t との差が 1pt 未満なら v4t とする。
  - 全文版（v4 / v4c / july）の dev-A 精度は参照として報告し、切り詰めによる精度の損失を定量化する。
  - **結果（第2パイロット）**: dev-A macro は v4t 0.784、v4ct 0.780、v4 0.764、v4c 0.791、july 0.782 だった。切り詰めによる損失は見られず、規則どおり v4t を採用した。
- **議論のゲーティング**（2026-09-30 追加。進化・評価の本実験に適用。世代0の選定は非ゲーティングの v4t で実施済み）:
  - 連合の round0 の回答が全員一致なら議論（round1）を行わず、その回答を最終回答にする。一致しなければ v4t で議論する。
  - 根拠は3つ。(1) 第1パイロットで、多数派が議論後も答えを維持した率は 93〜95% だった。(2) dev-A の既定トリオで、非ゲーティング 0.784 に対しゲーティング 0.789（+0.4pt）で、損失はなかった。(3) round1 の約6割を省ける（全員一致率 59%）。これは round1 が KV キャッシュ律速で高価なためである。
  - 実際に議論する呼び出しは v4t と同一なので、生成済みの v4t の round1 はそのまま再利用する。
- **世代0のペルソナ**（根拠: `docs/review_2026-09/persona_design.md`）:
  - **候補**: Belbin の9チーム役割をすべて使い、それぞれを確立した推論手続きとして英語1〜2文で操作化する。対照としてペルソナなし（plain）を1体加える（`configs/v4/persona_pool.json`）。元の3人（critic / pragmatist / explorer）は Monitor Evaluator / Implementer / Plant に対応し、これを既定トリオとする。
  - **段階1**（dev-A）: 単独精度を測る。plain より macro で 2pt 以上低く、かつ 90%CI の上限が 0 未満の役割は、能力税ありとして最終選択から除く。
  - **段階2**（dev-A）: アフィン平面 AG(2,3) の釣り合い型12チーム（各役割が4チームに入り、各ペアが1回ずつ同じチームになる。9つは3群から1人ずつのバランス型）＋既定トリオ＋plain×3 を議論させる。加法モデルで役割の主効果を推定する。バランス型と同質型の差は探索的に検定する。
  - **段階3**（dev-B）: 最終候補を確認する。候補は F0（既定トリオ）、F1（観測最良）、F2（主効果の上位3）、F3（単独の上位3）、C（plain×3）。**B の macro が最大の F\* が F0 を +1.5pt 以上上回り、かつ 90%CI 下限 > 0 のときだけ F\* を採用する。それ以外は F0。** 採用チームについて、厳密 Shapley と Banzhaf を B で報告する。
  - 採用したペルソナ文は、全系統・全世代で固定する。
- **クライアント並列数**: 出力 tok/s が最大になる値。
- **反復ループの早期打ち切り**: 誤検知（正答した出力の打ち切り）が見つかれば無効化する。
- **クライアント並列数**: 出力 tok/s が最大になる値。
- **反復ループの早期打ち切り**: 誤検知（正答した出力の打ち切り）が見つかれば無効化する。
