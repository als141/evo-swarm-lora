## 0. v3が答える問い

> **4B級LLMのLoRAペルソナ・チームは、同一計算量のSelf-Consistencyを、全領域で上回れるか。**
> 上回れないなら、その境界はどこにあり、何が律速か。

v1の実測は「MMLU-Proで勝ち・MATH/SuperGPQAで負け・総合タイ〜負け」だった。
本設計は敗因を**3つの独立な損失**に分解し、それぞれに実測ゲート付きの処方を与える。

## 1. 実測診断 — 何が足りなかったか

### 1.1 確定成績表（K=3シード平均、SuperGPQAはseed1のみ）

| 条件 | MMLU-Pro | MATH-500 | SuperGPQA(s1) |
|---|---|---|---|
| c1 ベース単体 | 0.639 | 0.830 | 0.407 |
| c2 SC@9 | 0.671 | 0.862 | 0.457 |
| c3 素の議論 | 0.598 | **0.870** | 0.467 |
| c3' プロンプトペルソナ議論 | 0.627 | 0.860 | **0.487** |
| c4 gen0 LoRAチーム | **0.684** | 0.770 | (測定中) |
| c5 進化後LoRAチーム | 0.683 | 0.813 | 0.387 |
| c6 進化後solo最良 | 0.661 | 0.698 | 0.343 |

検定確定分: LoRAチームvsベース +4.4pt (p=0.001)、vs SC@9 +1.6pt (p≈0.34 非有意)、
素の議論の悪化 −4.1pt (p=0.0035)〔以上MMLU-Pro〕。進化の修復 +4.3pt (p=0.0007)〔MATH〕。

### 1.2 損失の3分解（2026-07-05の新分析、seed1）

チーム精度 = oracle上限 −（集約損失）、oracle = f(個体能力, 多様性) という恒等分解で:

| ベンチ | solo平均 | oracle(≥1体正解) | 多数決(r0) | 議論後チーム | **集約損失(oracle−チーム)** |
|---|---|---|---|---|---|
| SuperGPQA | 0.335 | **0.517** | 0.363 | 0.387 | **0.130** |
| MMLU-Pro | 0.673 | **0.800** | 0.702 | 0.714 | **0.086** |
| MATH-500 | 0.667 | 0.815 | 0.705 | 0.813 | **0.002** |

**発見A（能力損失 L1）**: ペルソナSFTがsoloを −7.2pt（SuperGPQA）〜 −13pt（MATH L5）毀損。
原因は SFTデータが平均779字の短い応答のみ（ベースは8192トークン級の長CoTで解く）＋
rank32・lora_alpha64・lr 2e-4・3epochs という60例には過剰な学習圧。リプレイ（能力アンカー）なし。

**発見B（集約損失 L2）**: 毀損した3体ですら「誰かは正解」が51.7%ある（ベース0.407を+11pt上回る）のに、
多数決＋1ラウンド議論はそれを 0.387 しか回収できない。**正解が少数派のとき多数決は構造的に負ける**。
一方MATHでは集約損失がほぼゼロ＝**検証可能領域では正しい解が議論で説得力を持ち自然に採択される**。
議論1ラウンド自体の寄与は +1.2〜2.4pt に過ぎない。集約こそが最大の未回収資源。

**発見C（探索損失 L3）**: 進化演算子は α∈[0.3,0.7] の内挿ブレンド＋小変異のみ＝**親の凸包の内側しか探索できない**。
実測でも ΔW ノルム完全不変（比1.00）の「方向回転」であり、平均化によるSFT損傷の除去（=修復）が正体。
加えて適応度100問の SE±4.9pt に対し毎世代1-2pt差で最大値選抜 → 勝者の呪い（dev+12pt/test±0で実証）。

**発見D（効く帯域）**: SuperGPQA難易度層別で、素の議論は hard帯 +17.3pt（0.493 vs 0.320）、
easy/middle帯 +2〜4pt。議論の価値は「ベース精度が低く多様な試行が正解を拾う帯域」に集中する。
ベンチ間の勝敗も同じ軸で整理できる（MMLU-Pro 0.64 / SuperGPQA 0.41 / MATH 0.83 = 上限近い）。

**発見E（ペルソナ実装の対照)**: プロンプトペルソナ（日本語1文）は MMLU-Pro でチームに−5.9pt有意で負け、
SuperGPQA では 0.487 で全条件の首位。**重み焼き込みの付加価値は毀損の制御に成功した場合のみ普遍化する**。
これが run002 の中心仮説になる。

### 1.3 視点の欠落の総括（自己批判）

1. **SFTを「スタイル注入」としてのみ設計し、能力保持を設計変数にしていなかった**（リプレイ・低rank・低lrの検討漏れ）。
2. **集約を素朴な多数決に固定**。confidence抽出は run_debate_local.py に実装済みなのに評価系（evalx）へ未接続。
   oracle−チームのギャップ（8.6〜13pt）という最大の資源を放置していた。
3. **ペルソナ=性格（日本語1文）**であり、推論戦略の多様性（解法の直交性）として設計していなかった。
4. **進化=内挿**で新形質を生めず、**適応度=固定100問**で選抜が統計的に無意味だった。
   多様性（誤り相関）が目的関数に入っておらず、アンサンブル理論（チーム誤差=平均個体誤差−多様性）と接続していなかった。
5. **「議論が効く帯域」(ベース精度40〜70%・hard問題)の事前マッピングを怠った**。適応度セットにこの信号を使えていなかった。
6. ベンチ選定で MATH-500(0.83) は上限に近く、チーム化の伸びしろ自体が小さい。

## 2. v3の設計原理

- **P1 能力はアンカーで守る**: 自己生成リプレイ混合＋学習圧の適正化（rank16・lr 1e-4・2ep）。
- **P2 集約は「検証」を使う**: 多数決をやめ、confidence表明＋検証者裁定（judge集約）で oracle を回収する。
  MATHで実証された「検証可能なら集約損失ゼロ」を、検証器の明示的導入で知識領域へ移植する。
- **P3 多様性は戦略で作る**: 性格ペルソナ→推論戦略ペルソナ（導出・検証・具体例）へ。誤り相関の最小化が目標。
- **P4 進化は測れる差だけ選抜する**: hard層化マルチタスク適応度＋successive halving＋誤り相関ペナルティ、
  演算子に外挿（DARE式drop+rescale・TIES符号合意）を追加。
- **P5 全変更は実測ゲートを通す**: 下記§5の階段。ゲート不合格の変更は本採用しない（p-hacking排除の二段構えは維持）。

## 3. 具体設計

### 3.1 SFT v3（run002）
- データ: 各ペルソナ60例（既存）＋**リプレイ36例**（ベース自己生成の検証済み正解長CoT。
  MATH train L4-5 24例〔Intermediate Algebra/Precalculus/Geometry厚め〕＋ MMLU-Pro val 12例）。
  リプレイにはペルソナ system をそのまま付与（スタイルはペルソナ例が、能力はリプレイ例が担う）。
- ハイパラ: rank16 / lora_alpha 32 / lr 1e-4 / 2 epochs（v1: rank32・alpha64・lr2e-4・3ep からの緩和）。
- 検収基準（G1ゲート）: solo で MATH-500 ≥0.75（v1: 0.65-0.70）かつ SuperGPQA ≥0.37（v1: 0.33-0.34）
  かつ MMLU-Pro ≥0.63（劣化しないこと）。

### 3.2 議論・集約 v3（文献確定版）
- 更新則: `--debate-style conditional`（自己誤りを特定できた場合のみ変更可。実装済み・A/B判定待ち）。
  文献裏付け: 議論単体は信念のマルチンゲール＝期待正解率を改善しない（Debate or Vote, 2508.17536,
  NeurIPS25 Spotlight）。条件付き更新は同論文の「訂正方向への信念更新バイアス介入」の実装形。
- **発言の匿名化**（追加・訓練不要）: 議論プロンプトの `--- Agent {name} ---` から役割・人格ラベルを外し
  匿名ラベル化。sycophancyはself-biasより優勢で、匿名化だけで発言の重みが均等化（2510.07517）。
- **confidence**: verbalized（0-10自己申告）は**採用しない**——4B級では80-100%に飽和し較正不能
  （2502.11028, 2604.01457）。代わりに **logprobベースのtoken-level confidence**（DeepConf式, 2508.15260 /
  CISC, 2502.06233）で低品質トレースの除外+重み付き投票。vLLMのlogprobs取得のみで訓練不要。
- **GenSelect型裁定（新規・本命）**: 多数決が割れた問題（2-1 / 1-1-1）のみ、3体の最終解を
  **匿名化・順序ランダム化**して1コンテキストに並べ、ベースモデル（LoRAなし）に比較選択させる。
  文献: GenSelect（2507.17797）は「候補数が少ないとき多数決より有利」、reasoning tree監査（2602.09341）は
  多数決比+5pt絶対。4Bは採点型judgeには信頼性不足（2606.19544）だが**比較選択形式なら機能**する。
  position bias（2406.07791）対策に順序ランダム化、self-preference（2410.21819）対策に匿名化を併用。
- 計算量: チーム = 3×(1+1ラウンド) + 裁定(割れ時のみ≈0.4回) ≈ **6.4生成** < SC@9 の9生成。
- 対照条件（査読対策・公平比較）: 素朴SC@9に加え **SC@9+logprob重み付き投票（CISC式）** と
  **SC@7+GenSelect裁定（=8生成）** を1シードで測り、「利得がチーム固有か、集約改善一般か」を切り分ける。
- 参考: RSA（2509.26626）は**同一モデルQwen3-4B-Instruct-2507**で集約ループにより frontier 級到達を報告
  （SuperGPQA含む）。我々のdebate round1は「他者解を材料に各自が統合・再導出する」RSAの1ステップと同型
  であり、更新プロンプトを「批判」から「統合・再導出」へ寄せる文言も conditional スタイルに含める。

### 3.3 ペルソナ v3（推論戦略型・英語）— run003（時間ゲート付き）
- Deriver: 第一原理からの順方向厳密導出。 Verifier: 逆方向検証・選択肢消去・独立検算。
  Lateral: 具体例代入・極端ケース・類推。
- SFT例は同一リプレイCoTを戦略別プロンプトで再生成して作る（正解検証付き）。
- run002（既存ペルソナ+リプレイ）がG3不合格のときのみ昇格。時間がなければ修論はrun002まで。

### 3.4 進化 v3（run002合格後のみ・G4）
- 適応度セット: ランダム抽出をやめ、**識別力ベースの厳選**（tinyBenchmarks 2402.14992 / MERGE³ 2502.10436
  の方針）。実装は簡易IRT近似——**c1実測per_itemで正解率30-70%の問題（識別力最大帯）を優先**し、
  MMLU-Pro/SuperGPQA/MATH混合の層化120問を世代ごと再サンプル。SuperGPQA hard を1.5倍加重
  （発見D: 議論ゲインの信号が最大の帯域で選抜する）。
- 目的関数: チーム精度（v3集約で測る）− λ·平均pairwise予測一致率（λ=0.1）。
  理論裏付け: アンサンブル選択のMI最大化定式（2602.08003）——高性能個体だけ足しても誤り相関で飽和する。
- 選抜: successive halving（2404.00069: 評価数2×削減で同等選抜）— 全候補を60問で足切り→上位半分を
  300問で確認。**300問（SE±2.8pt）で2pt以上の差のみ採用、それ未満は「同点」として複数候補を持ち越す**
  （oracle選抜の正バイアスは構造的: 2606.26836）。
- 演算子: 従来ブレンドに加え **DARE式 drop+rescale（p=0.3-0.4、DELLA 2406.11617 の最適0.4に準拠。
  高drop率はSFT deltaが小さい場合の性質でありLoRA ΔWには危険）** と **TIES符号合意マージ** を混ぜ、
  凸包の外への探索を可能にする。交叉は2-3個の少数に維持（マージ利得は凹: 2505.21226）。
- 中止条件: 3世代で val（150問）+2pt 未達なら進化は打ち切り、run002チームを最終とする。

### 3.5 評価 v3（プロトコルは現行を維持）
- 3ベンチ×3シード×McNemar+bootstrap+Holm は不変（v1結果と直接比較可能に保つ）。
- 追加条件: c7 = run002チーム（judge集約）、c8 = SC@7+judge 対照。適応度セットとの重複除外は現行踏襲。

## 4. 数値シナリオ — 「上がる」根拠は実測値の組み合わせ

以下は希望値ではなく、**すべて今回実測された量の再結合**である。

| 量 | 実測値 | 出所 |
|---|---|---|
| チーム化ゲイン（solo→チーム） | +5.2pt (SGPQA) / +4.1pt (MMLU) / +11.5pt (MATH) | c6→c5 |
| oracle−チーム（集約で回収可能な上限） | +13.0pt / +8.6pt / +0.2pt | §1.2 |
| SFT毀損（リプレイで修復を狙う量） | −7.2pt / −1.2pt(solo最良比) / −13pt(L5) | c6 vs c1 |
| 議論のhard帯ゲイン | +17.3pt (SGPQA hard) | 層別分析 |

シナリオ（保守的: 毀損の半減＋集約損失の1/3回収のみ仮定）:
- SuperGPQA: solo 0.335→0.37 ⇒ oracle≈0.55 ⇒ チーム 0.42→judge回収+4pt ⇒ **0.46**（SC@9=0.457と同等以上）
- MMLU-Pro: solo 0.673→0.69 ⇒ チーム **0.72-0.73**（SC@9=0.671に+5pt、現状でも+1.6pt）
- MATH-500: solo 0.667→0.75 ⇒ 集約損失ゼロ型 ⇒ **0.84-0.86**（SC@9=0.862と同等）
- **プール(3000問): ≈0.66-0.67 vs SC@9 0.643 ⇒ +2〜3pt、McNemar有意圏**。

強気シナリオ（毀損全快＋judge がc3p水準の多様性を回収）では SuperGPQA 0.49+/プール+4pt。
悲観シナリオ（リプレイがペルソナ多様性を消しチームゲイン半減）でも MMLU-Pro の優位は残り、
「領域依存性＋損失分解＋部分修復」の因果研究として着地する（§6）。

## 6. 修論への位置づけ（どちらに転んでも成立する二段構え）

- 実験1（完了・v1）: チーム効果の実証と**故障の診断** — 領域依存性、損失3分解、勝者の呪り、追従の実例。
- 実験2（本設計・run002+）: **処方の因果検証** — リプレイ（L1）、judge集約（L2）、進化v3（L3）の各処方が
  対応する損失を狙い通り削るかを、ゲートの合否として報告する。
- 主張の最終形（成功時）: 「重みペルソナ・チームは、能力アンカーと検証型集約を備えたとき、
  同一計算量のSCを全領域で上回る」。失敗時: 「上回れない境界条件と、その損失構造の同定」。

## 7. 文献調査の反映結果（2026-07-05 確定、詳細は literature_notes_v3.md）

- [x] **judge集約**: GenSelect型比較選択（採点型は4Bで信頼性不足）。匿名化+順序ランダム化必須。
  多数決が割れた問題のみ起動 → §3.2に反映。
- [x] **confidence**: verbalized は4Bで飽和し不採用。logprobベース（DeepConf/CISC式）に決定 → §3.2。
- [x] **DARE/TIES**: drop率0.3-0.4（DELLA最適0.4）。SVD整列後適用が安全 → §3.4。
- [x] **リプレイ比率**: 36/96≈38%は文献レンジ（10-50%）内。比率より「ベース自身の生成分布であること」が
  支配的（2506.09428/2505.13811）——make_replay_data.py の設計はこの条件を満たす → §3.1。
- [x] **novelty再確認**: チームレベルShapley適応度×LoRA集団進化の交点は依然未報告（2026-07-05調査）。
  最近接は ACPO（2602.09341、反合意選好最適化）——引用・対比必須。
  素の議論のMATH有効性（+4.0pt有意）は「マルチンゲール定理（2508.17536）への領域依存の反例」として論述。
