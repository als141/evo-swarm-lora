# 研究設計 v2 — 汎化する進化への再設計（2026-07-04）

v3最終評価の実測に基づく診断と、それに対する最小限・文献裏付けありの設計変更。
v1/v3 の設計は `research_design.md` を参照。本書は差分のみを定義する。

---

## 1. v3実測からの診断（何が壊れているか）

| # | 症状（v3実測） | 根本原因 |
|---|---|---|
| D1 | MATH-500でLoRA個体のsoloが 0.84→0.65-0.69 に劣化。チーム議論でも0.81でベース未満 | **ペルソナSFTによる能力破壊**。60例・rank32・3epochsは文体に対して過剰で、SFTデータ（GSM8K風算数・択一・日本語タスク）の分布外にある競技数学の能力を上書きした。能力保持（リプレイ）データが皆無 |
| D2 | 進化が開発セット+12pt → MMLU-Proテスト±0pt（c4 0.684 vs c5 0.683） | **固定100問・単一タスクの適応度への過適合**。全6世代で同一のMMLU-Pro 100問を使い回し、タスク多様性なし、世代選択に検証セットなし |
| D3 | MMLU-Proで全問debateは6生成/問と高コスト。実測では round0 で3体一致が64% | **合意済みの問題にも議論コストを払っている**。世代あたり評価コストが高く、世代数(6)や集団サイズ(2/役割)を制約 |

付随する実測知見（保持すべき強み）:
- チーム(0.683-0.684) > SC@9(0.667) > ベース(0.639) > プロンプトペルソナ議論(0.624) > 素の議論(0.598) — **重みに焼き込んだ多様性×議論の効果は本物**（MMLU-Pro 3シード一貫）
- 議論はsolo多数決の誤り44問を修正/26問を悪化（差引+3.6pt、500問）
- MATH-500では素の議論(0.860)が単体(0.840)に勝つ — 検証可能なタスクでは議論自体が機能する

## 2. 設計変更（5点、シンプルさ優先）

### V2-A. 能力保持型ペルソナSFT（D1対応）
- 各ペルソナのSFTデータ60例に **能力リプレイ30例** を追加:
  ベースモデル自身に MMLU-Pro validation split / MATH 訓練split (L4-5) / SuperGPQA除外分 を解かせ、
  **正解したCoTをそのまま**（ペルソナ文体に書き換えず、ただしANSWER:形式で）追加する。
  self-generated replay は外部データ不要で、経験リプレイは最小コストで最も効果的な忘却対策
  （experience replay系文献、GeRe、LoRA-Loop 2507.13568）。
- LoRA強度を下げる: rank 32→16、epochs 3→2。
- **能力ガード**: 学習後に MATH mini-guard（訓練split 40問）で solo 精度を測り、
  ベース比 -10pt 超の劣化なら不合格（LR/epochsを下げて再学習）。
  「各ステップ後に旧能力を代表セットで監視する」は継続学習の標準プラクティス。

### V2-B. マルチタスク適応度 + 世代ごと再サンプル（D2対応）
- 適応度プール: MMLU-Pro(test, 最終評価シードと排他) 600問 + MATH訓練split L4-5 300問 + SuperGPQA 300問。
- 各世代、プールから **層化再サンプルで120問**（60/30/30）を世代シードで抽出。
  世代内は全候補・全連合で同一セット（ペア比較・厳密Shapleyは従来どおり成立）。
  動的リサンプルは進化計算の標準的な過適合対策であり、縮小セット評価の有効性は
  MERGE³ (2502.10436) がIRT推定で示している。
- 効果: 「特定100問の暗記」が選抜圧にならない。タスク混合により D1 の再発も適応度が罰する。

### V2-C. 検証セットによる世代選択（D2対応）
- 固定検証セット150問（3タスク混合、適応度プール・最終評価と排他）を用意し、
  **毎世代の代表チームを測定**。最終チーム = 検証最良世代（last-genではない）。
  early stopping / model selection の定石をEAに適用するだけ。実装は evolve loop に1評価追加。

### V2-D. DARE/TIES系の進化演算子（D2/D3補助）
- 交叉: ΔW空間ブレンド（現行）に加え **TIES式の符号合意マージ** をオプション化。
- 突然変異: ガウスノイズ → **DARE式（確率pでドロップ+1/(1-p)リスケール）** に置換。
  ΔWパラメータの90-99%が冗長で、ドロップ系演算は干渉を減らす（DARE 2311.03099、
  PopuLoRA 2605.16727 も同系演算子を採用）。実装は lora_ops.py に小関数2つ。

### V2-E. 議論の効率化 + confidence重み付き投票（D3対応）
- **合意時スキップ**: round0 で3体の回答が一致したらその回答を採用し round1 を省略。
  実測64%一致 → 議論コスト約6割減。不一致時のみ従来の批判的更新ラウンド。
  自信度による early-exit は SID (2510.06843) 等で有効性が示されている。
- **confidence重み付き投票**: 最終行を `ANSWER: X | CONFIDENCE: 0-10` とし、
  多数決を confidence 重み付き集計に置換（ConfMAD 2509.16839 系）。同点処理は従来どおり。
- 節約分を世代数に回す: 6世代 → **10世代**、候補数も 2→3/役割 に増やす。

## 3. 実験計画 v2

| ステップ | 内容 | 資源 | 概算 |
|---|---|---|---|
| 1. リプレイ生成 | ベースモデルで3タスクのCoT自己生成→正解のみ抽出（各30例×3ペルソナ+ガード40問） | A100 Spot 〜1h | $1-2 |
| 2. ペルソナ再学習 | 3×(60+30例), rank16, 2epochs + 能力ガード | T4 Spot 〜3h | <$1 |
| 3. 進化v2 | 10世代×3役割×3候補、V2-B/C/D/E 適用 | A100 Spot 〜5h | $6-8 |
| 4. 最終評価 | 新規条件のみ: c4'(gen0') c5'(evolved') c6' ×3ベンチ×3シード=27エントリ。c1/c2/c3/c3p は v3 の値を再利用（ベース条件は設計不変） | A100 Spot ×2〜3本 | $15-20 |
| 合計 | | | **$25-30** |

- 予算: v3までの消費 ~$110-130 + v2 ~$30 = 残余内に収まる見込み。
- 修論の構成: v3 = 実験1（診断: チーム効果の実証と過適合・能力破壊の特定）、
  v2 = 実験2（処方: 汎化する進化）。**実験1→診断→実験2という物語は、
  仮にv2の上積みが小さくても「原因を特定し対策の効果を測定した」研究として成立**する。
