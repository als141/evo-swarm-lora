## 0. 要点

1. **【最重要・修論の主張に直結】旧環境（実験1）の MMLU-Pro において、ベースモデル系4条件（c1/c2/c3/c3'）は回答抽出の旧バグで大幅に過小評価されていた（§3）。** 修論 §4.6.4 の「評価イメージ間の系統差 +6pt（ベース素生成に選択的）」の正体は、生成の差ではない。採点コードの修正（`Final answer:` の次行の `ANSWER: X` を旧正規表現が「ANSWER: X」ごと拾い、letter 型で単語 ANSWER の **'A'** を抽出していた）が、MMLU-Pro の再採点を伴わずに途中で入ったことによる差である。旧環境 MMLU-Pro の予測 'A' 率は、ベース系で 20〜30%（正解の 'A' 率は 11.5%）、LoRA 系で 11〜12% だった。新環境の生成全文に旧ロジックを当てると、ベース単体の MMLU-Pro 精度は **−9.7pt**、SuperGPQA も −9.1pt 下がる。これで旧→新の差（MMLU-Pro +8.7pt、SGPQA −0.4pt: SGPQA は旧環境時点で修正済み）を定量的に説明できる。
   → 実験1の「MMLU-Pro では LoRA チームのみ有効（対ベース +4.3pt）」「素の議論は MMLU-Pro で有害（−4.1pt）」「ベンチマーク依存の反転／2軸トレードオフ」は、**MMLU-Pro の脚が成立しない**。有効な新環境では、旧 LoRA チーム c5 はベース単体に MMLU-Pro で **−4.2pt**（0.685 vs 0.727）である。
2. **測定ノイズの床**: 進化ログで同一連合（同一 seed 777・同一 100 問）を再測定した値の SD は、solo 3.2pt、2体 3.3pt、3体 0.9pt（ただし 3体は自由度3と少ない）。seed 固定でも再測定値は最大 10pt 動く。
3. **進化の選抜はノイズ判定だった**: 候補間 Shapley 差の中央値は 1.17pt で、誤差伝播によるノイズ SD は 1.9〜2.3pt。18 件の選抜のうち 67% が |z|<1、100% が |z|<2 だった。観測された差の二乗平均（0.00028）は純ノイズの期待値（0.00036）を下回り、**候補間に真の差の分散は検出されない**（真の差の SD≈0）。
4. **行動距離＝サンプリングノイズ**: 進化ログの同役割間の不一致率（平均 0.358）は、同一 LoRA を別 seed で再サンプリングした 512 トークン相当の不一致率（c5 MMLU-Pro 0.350）と同じだった。
5. **ペルソナ LoRA の多様性は再サンプリングと区別できない**: 同一問題集合で比べると、「同一エージェントの別 seed」と「別ペルソナ」の不一致率の差は −0.5〜+1.4pp しかない。チーム3体の oracle@3 もベースの 3 サンプルの oracle@3 以下だった（MMLU-Pro 0.785 vs 0.788、MATH 0.878 vs 0.886、SGPQA 0.544 vs 0.564）。
6. **seed による common random numbers（CRN）は限定的にしか効かない**: 完全同一リクエスト（同モデル・同プロンプト・同 seed）の反復でも、応答がバイト一致したのは **0.9%（4/459）** だった。回答の不一致率は 0.296 で、別エージェント間の 0.387 より約 24% 低い程度である。重みが少しでも違う候補同士では、相関はほぼ消える（上記4）。
7. **議論は「多数派への同調」でほぼ決まる**: round0 で少数派だったエージェントは、**自分が正解でも 81〜95% の確率で誤った多数派へ回答を変える**（c7 条件付き更新でも同様）。原因は実装上の欠陥と考えられる。round1 のプロンプトに自分の前回解答が含まれないため、自分の答えを「維持」できない。
8. **議論の上積みは小さい**: 最終精度と r0 多数決の差は、c7 で +0.8〜+1.8pt、c5 で +1.6〜+4.1pt。集約損失（oracle@3 − 最終）は c7 で 6.9 / 1.2 / 11.3pt（MMLU / MATH / SGPQA）。
9. **問題の大半は情報を生まない**: ベースが 9 サンプル以上で「全問正解」または「全問不正解」になる問題の割合は、MMLU-Pro 76%、MATH 70%、SGPQA 62%。中間帯（0.2〜0.8）の問題は、系統対の不一致率が平均の 2.2〜4.5 倍ある。一方で p=1 帯は、能力毀損（c5）の検出に効く（c7 vs c5 の差の 60% が p=1 帯で生じる）。
10. **dev の大きさの目安**（真の差 3pt の系統対で「正しい方を選ぶ確率」PCS）: 無作為 100 問で 0.77、300 問で 0.90〜0.92、1,000 問で 0.995。中間帯を 70% に濃縮した 300 問なら 0.96。**差が 1〜2pt の候補の選別には、1 候補あたり数千問相当の評価が必要**になる（§5.4）。
11. **予算の較正**（A100 40GB・クライアント並列 32 の実測）: 1,000 問（500/200/300）の評価にかかる時間は、チーム（6 呼び出し/問）2.28 A100·h、SC@9 4.36 A100·h、ベース単体 0.47 A100·h。$2.2/h 換算でそれぞれ約 $5.0、$9.6、$1.0 になる。出力スループットはチームで ~720 tok/s、SC で ~1,080 tok/s。並列 32 ではまだ GPU が飽和していない（同時実行数にほぼ比例してスループットが伸びる）。
12. **無駄の所在**: max_tokens（8192）到達呼び出しは全体の 2〜6% にすぎないが、出力トークン（＝時間）の **10〜22%** を消費し、その正答率はほぼ 0（MATH 0〜2%）である。一方、一律に 4096 で打ち切るとベース単体の精度が −2.9 / −8.2 / −3.9pt 下がるため不可。反復検出による早期停止が有望である。

## 1. 【解析1・5】測定ノイズの床と Shapley 値の情報量（`ra1_evolution_noise.py`）

進化ループは世代ごとに連合評価キャッシュを作り直し、全世代で同一の適応度セット（MMLU-Pro 100 問、seed 777）と同一の生成 seed で測り直している。したがって、同じメンバー構成の連合が複数世代に現れれば、それは同一条件の再測定になる（生成条件は max_tokens=512）。

### 1.1 再測定の SD（同一 seed・同一 100 問）

| 連合サイズ | 連合数 / 測定回数 | pooled SD | 100 問二項 SE（p̄ で） | 比 | 平均 \|差\| | 最大 \|差\| |
|---|---|---|---|---|---|---|
| solo | 10 / 25 | **3.19pt** | 5.00pt | 0.64 | 4.1pt | 10pt |
| 2体 | 10 / 21 | **3.28pt** | 4.99pt | 0.66 | 3.3pt | 10pt |
| 3体 | 3 / 6 | 0.91pt（自由度3） | 4.88pt | 0.19 | 1.0pt | 2pt |

- 二項 SE より小さい（比 0.64）のは、問題難易度が不均一で常時正解・常時不正解の問題が多いためである。実効分散は E[p(1−p)] で決まる（§5.3）。
- **seed を固定しても値は動く**。例: `gen0_critic_base` の solo は 0.53 → 0.46 → 0.56。vLLM のバッチ依存の数値差が、サンプリング経路を分岐させるためである（§2.1）。

### 1.2 Shapley 値の誤差伝播と 18 件の選抜

φ_c = v(c)/3 + [v(c,ρ1)−v(ρ1)]/6 + [v(c,ρ2)−v(ρ2)]/6 + [v(T)−v(ρ1,ρ2)]/3。連合値の測定誤差を独立とみなし、候補差では代表のみの連合が相殺されることを使う。

| 量 | σ3=0.91pt（実測） | σ3=3.1pt（保守的） |
|---|---|---|
| SD(φ) | 1.89pt | 2.07pt |
| SD(φa − φb) | **1.91pt** | **2.31pt** |

| 選抜の診断（18 件＝6世代×3役割） | 値 |
|---|---|
| 候補間 \|Δφ\| の中央値 | **1.17pt** |
| \|Δφ\|/SD(Δφ) の中央値 | **0.61**（\|z\|<1: 67%、\|z\|<2: 100%） |
| 観測 E[Δφ²] vs 純ノイズ期待値 | 0.00028 vs 0.00036 → **真の差の SD≈0** |
| 真の差 δ で正しい方を選ぶ確率（SD=1.91pt） | δ=1pt: 0.70 / 2pt: 0.85 / 3pt: 0.94 / 5pt: 0.996 |
| Shapley 選抜と solo 最大の一致率 | 44%（solo 同点 2 件） |
| Shapley 選抜と team 最大の一致率 | 61%（同点 2 件） |

### 1.3 勝者の呪い（チーム水準）

各世代の「最大候補チーム精度（選抜時）」と、選ばれた代表からなる評価文脈チームを次世代で再測定した値の比較:

| 世代 | 評価文脈チーム（前世代の代表を再測定） | 当世代の最大候補チーム |
|---|---|---|
| 0 | 0.56 | 0.63 |
| 1 | 0.63 | 0.63 |
| 2 | 0.60 | 0.63 |
| 3 | 0.57 | 0.65 |
| 4 | 0.60 | 0.61 |
| 5 | 0.59 | **0.68**（最終チーム。ループ内で再測定されず、最終評価では c4 と差なし） |

選抜時の最大値は、次世代の再測定で平均 −3.2pt 下がる（5 遷移）。「dev +12pt」（0.56→0.68）は、最終世代の最大値を拾った見かけの改善である。注意: 3役割の代表は独立に選ばれるため、文脈チームと前世代の最大チームは厳密には同一でない場合がある。

### 1.4 Shapley 値と solo・team の関係（解析5; 36 個体-世代, ノイズ支配に注意）

| 相関 | r |
|---|---|
| Shapley vs solo 精度 | −0.08 |

### 3.3 機構の特定: 旧抽出ロジックを新環境の生成全文に当てる

`extract_answer` の二重 prefix 剥がし（コミット 9b0fcd6 で追加）を外した旧ロジックを、新環境の生成全文に適用した:

| 呼び出し | 抽出が変わる率（すべて偽 'A'） | 現行精度 → 旧ロジック |
|---|---|---|
| ベース単体 MMLU-Pro | 12.6% | 0.727 → 0.630（**−9.7pt**） |
| ベース SC サンプル MMLU-Pro | 12.7% | 0.724 → 0.631（−9.4pt） |
| ベース単体 SuperGPQA | 15.6% | 0.431 → 0.340（−9.1pt） |
| c5 LoRA r0/r1 | **0.0%** | 変化なし |
| c7 LoRA r0 / r1 MMLU-Pro | 3.9% / 1.6% | −2.9 / −1.0pt |

- **機構**: 正規表現 `ANSWER\s*[:：]\s*(.+)` の `\s*` は改行もまたぐ。ベースモデルは `Final answer:` と書いてから、次行に `ANSWER: H` を書くことが多い。旧ロジックはこの 2 行を 1 つの一致としてまとめて拾い、捕捉部が「ANSWER: H」になる。letter 型では、その先頭の単語 ANSWER の 'A' を抽出していた。
- ペルソナ SFT 済み LoRA は、この書き方をしない（c5: 0%）。そのため、差は「ベース素生成に選択的」に見えた。
- SuperGPQA は、旧環境でも修正後のコードで走っていた（予測A率が新旧で同水準）。旧ロジックを当てれば −9pt 動くはずなのに、実際の旧→新差は ±1pt だったからである。つまり、実験1のうち **MMLU-Pro のエントリだけ**が修正前のコードで採点され、再採点されないまま残っていた。
- 「予測一致率 86%」（修論 §4.6.4）の内訳: 抽出修正による置換（c2 旧の過剰 wrong-A 約 9pp）と、SC 多数決の再サンプリング不一致（別 seed で 7%）で説明がつく。

### 3.4 修論への影響（要修正）

| 修論の主張 | 判定 |
|---|---|
| §4.6.4 評価イメージ間の系統差 +6pt（依存ライブラリ起因、ベース素生成に選択的） | **原因の帰属が誤り**。採点コードの途中修正（MMLU-Pro 未再採点）。vLLM の非決定性（§2.1）は別の実在の現象 |
| 実験1 LoRA チームは MMLU-Pro でベースに +4.3pt（p=0.0004） | **不成立**。新環境の有効値は c5 がベースに −4.2pt |

| ベンチマーク依存の反転・2軸トレードオフ（貢献 a） | **MMLU-Pro の脚が消える**。有効なのは MATH（素の議論 +4.2pt）と SGPQA（+3.1pt）だけで、どちらも「素の議論は非有害〜有効」の向き |

## 7. v4 設計への含意（数値根拠つき）

1. **初期集団の多様性が最優先**: 現行の「SFT 個体＋2% ノイズ」は、行動上は同一個体の再サンプリングと区別できない（§2.3）。ペルソナ間の差ですら +1pp 程度しかない（§2.2）。選抜で意味のある 3pt 以上の差を生むには、データ・学習レシピ・推論戦略など系統的に異なる個体を用意する必要がある。参考: 能力毀損の有無で約 3pt の差が生じた（c7 vs c5）。
2. **適応度の測定**: 100 問・単発では SD 約 3pt（§1.1）あり、選抜は硬貨投げと同等だった（§1.2）。1 判定あたり 300〜500 問の中間帯濃縮セットと、逐次半減法を使う。seed による CRN は、同一モデル・同一プロンプトの測り直しで正誤不一致を約 30% 減らすだけで、候補間の比較には効かない（§2.1）。
3. **fitness sharing の距離はノイズを測っていた**（§2.3）。多様性を扱うなら、同一問題の反復平均（r≥3）の距離を使い、再サンプリング不一致を差し引く必要がある。あるいは、別の多様性指標（誤り相関の減少、oracle 被覆の増分）を使う。
4. **議論プロトコルの修正**: round1 に自己の前回解答を含める。現状は少数派の正解が 95% の確率で多数派に同調しており（§4.4）、議論は実質「多数決の補強」にとどまる。
5. **評価の衛生**: 実験途中の採点コード修正は、既存エントリを全件再採点させること。生成全文は必ず保存すること。旧環境の MMLU-Pro 問題（§3）はこれを怠った結果である。
6. **予算の目安**（並列 32 の実測値。並列を上げれば短縮の可能性あり）:
   - チーム 1 構成×1,000 問 ≈ 2.3 A100·h（$5）
   - SC@9×1,000 問 ≈ 4.4 A100·h（$9.6）
   - 候補チーム 20 構成を 500 問の濃縮 dev で 1 回ずつ評価すると ≈ 23 A100·h（$50）。round0 のキャッシュ共有などで減らせる。
