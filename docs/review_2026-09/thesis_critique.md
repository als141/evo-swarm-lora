## 1. 新発見の詳細: 実験1 MMLU-Pro の回答抽出アーチファクト（致命）

### 1.1 症状: 「誤って A と答えた」率がベースモデル系条件だけ異常に高い

実験1（旧環境）の3シード合計で、予測が 'A' かつ不正解だった問題の割合を条件別に集計した。データは `results/gcs/run001/final_eval3/`。

| 条件 | MMLU-Pro 誤A率 | SuperGPQA 誤A率 |
|---|---|---|
| c1 ベースsolo | **15.5%**（233/1500） | 9.0% |
| c2 SC@9 | **12.5%**（188/1500） | 9.3% |
| c3 素の議論 | **21.9%**（329/1500） | 7.7% |
| c3′ プロンプトペルソナ議論 | **18.7%**（280/1500） | 8.1% |
| c4 gen0 LoRAチーム | 4.0% | 10.6% |
| c5 進化後LoRAチーム | 4.6% | 11.6% |
| c6 進化後LoRA solo（seed1） | 4.8〜7.2% | 12〜13% |
| （参考）新環境 c1 / c2 / c5 | 2.9% / 3.2% / 4.8% | — |

- 正解が A である問題の割合は、MMLU-Pro で 11.5%（172/1500）である。精度が約 0.7 のモデルなら、誤A率は理論上 3〜4% 程度になるはずだ（誤答 30% が 9 つの誤選択肢に分散するため）。
- ベースモデル系の4条件だけが MMLU-Pro で 12〜22% と異常値を示す。LoRA 系と SuperGPQA では異常がない。

### 1.2 機構

ベースモデル（LoRA なし）は、回答の末尾をしばしば次の形式で書く。

```
### Final Answer:
ANSWER: H
```

旧抽出器の正規表現 `ANSWER\s*[:：]\s*(.+)`（IGNORECASE）は、まず `Final Answer:` の `Answer:` にマッチする。このとき `\s*` が改行をまたぐので、捕捉される文字列は `ANSWER: H` になる。letter 抽出は、その文字列の先頭に現れる A〜J の文字、つまり「ANSWER」の **'A'** を返してしまう。

この「二重 ANSWER 接頭辞の除去」は 2026-07-04 のログで既知の不具合として修正された（`src/evalx/tasks.py:224-228`。コミットは 07-07 の 9b0fcd6）。一方、LoRA 個体は SFT で「`ANSWER: X` だけを書く」形式を学習している。このため LoRA 系はこのバグを踏まない。

### 1.3 検証: 旧抽出器を新環境の生出力に適用すると再現する

新環境の `llm_calls`（生出力の完全記録）に、旧抽出器（`git show f3fd2cc:src/evalx/tasks.py`）と現行の抽出器を両方適用した（付録A）。

- ベースモデルの 10 択 letter 呼び出し 34,608 件のうち、**9.1%（3,142 件）で抽出結果が変わった**。変化は全件「旧＝'A'、新＝'A' 以外」だった。
- エントリ別の内訳は次のとおり。
  - MMLU-Pro base solo: 10.6〜14.2%
  - SC@9 MMLU-Pro: 11.8〜12.9%
  - SuperGPQA base solo: 15.3〜16.0%
  - SC@9 SuperGPQA: 16.1〜16.8%
  - **LoRA チーム（c5）の呼び出し: 0.0〜0.1%**
- 新旧の差分の大きさとも整合する。旧→新（同一問題、3シード）の変化は次のとおり。
  - c1 MMLU-Pro 0.639→0.727（**+8.7pt**）。誤A率の超過分 12.6pt のうち約7割が本来正解だったと仮定すると ≈ +8.8pt となり、ほぼ一致する。
  - SC@9 MMLU-Pro 0.667→0.741（+7.4pt）。
  - c5 MMLU-Pro 0.683→0.685（+0.1pt）。

### 1.4 なぜ MMLU-Pro だけ汚染されたのか

- 研究ログ（AGENTS.md 2026-07-04）によると、math500 の書式バグを直す際に抽出器も修正し、評価イメージを再ビルドした（af9b340a）。その後にバッテリーを再投入している。
- **完了済みのエントリは再投入時にスキップされる設計**だった。修正前に完了していた MMLU-Pro の JSON は、修正前の抽出器で採点されたまま残った。一方、math500 は隔離して再実行され、SuperGPQA は再投入後に実行された。
- 傍証: 旧環境の SuperGPQA ベース 0.436 は新環境の 0.431 と一致する。旧抽出器が SuperGPQA に使われていれば、約 −6pt 以上低く出たはずである。

→ §4.6.4 の「評価コンテナイメージ間の系統差（依存ライブラリ差による +6pt、ベース素生成に選択的）」は、**抽出器修正の適用タイミングの問題を環境要因と誤認したもの**である可能性が極めて高い。「ベース素生成に選択的・LoRA ではほぼ不変」「MMLU-Pro 限定」という観察は、書式依存の抽出バグで完全に説明できる。

- **(必須)** 実験1の MMLU-Pro について、ベース系条件の数値と、それに依存する主張を本文から撤回する。代わりに次のどちらかを行う。

- **(必須)** §4.6.4 を書き直す。題材は「採点器の書式依存バイアス」とする。SFT で出力書式が揃ったモデルと、揃っていないベースラインの間に、採点器が非対称な誤差を生む現象である。検出経緯（頑健性シードの追加→不連続→再測定）と、原因の同定（旧抽出器の生ログへの再適用で 9.1% が偽 'A' に反転）を示せば、方法論的貢献としてはむしろ強くなる。ただし「コンテナの依存ライブラリ差」という推定は削除する。
- **(必須)** 採点器の監査を v4 に組み込む。条件タイプ（base/LoRA/debate/SC）×ベンチマークごとに無作為 100 件を手作業で照合し、誤抽出率を報告する。「誤A率」のような分布異常のモニタも自動化する。

### C. 実験設計の妥当性

**[C-01] 致命（v4 で解決すべき） — v1 進化は初期集団に遺伝的多様性がなかった**
- 箇所: Sec3.tex:174（初期化＝SFT 個体＋2% ノイズ変異体）、Sec3.tex:222-224（変異 σ=0.02 相対）、Sec3.tex:217（交叉親は代表と残余1体）
- 根拠: 各役割の集団は、同一 SFT 個体とそのほぼ複製だけで構成されていた。交叉しても子はほぼ親になる（cos 0.9998）。本文は「探索の不全」を事後に指摘しているが、手法章が設計として当然視している点が問題である。さらに進化ログでは、ほぼ同一重みの個体間の行動距離が 0.28〜0.45 あった。これは sharing が測っていたのがサンプリングノイズだったことを示す。
- 改善案（v4）: 初期集団を、実質的に異なる個体で構成する。
  - 異なるデータ部分集合・seed・ハイパーパラメータ・推論戦略ペルソナで学習した LoRA
  - 変異幅を「行動が変わる大きさ」に較正する
  - K≥4
  - 行動距離の測定には、同一個体の再サンプリング距離（ノイズ床）を差し引く、または共通乱数を使う

**[C-02] 重大 — 適応度評価がノイズ支配で、Shapley の「厳密性」は見かけ上のもの**
- 箇所: Sec3.tex:131（「近似誤差のない厳密Shapley値」）、Sec2.tex:104、Sec1.tex:45
- 根拠: Shapley は、7 個の特性関数値 v(S) の推定値（100 問、SE≈±5pt）から計算している。「近似なし」なのは連合の列挙だけで、推定誤差は大きい。進化ログでは、同一個体の solo 精度が世代間で 0.53→0.46→0.56 と変動した。
- 改善案: v4 では推定分散を明示的に扱う。
  - 共通乱数（エージェント ID で seed を固定し round 0 を全チームで共有）
  - 問題数の増加
  - 対応ありの比較
  - racing / 逐次半減
  - エリートの再評価
  「厳密」の強調は「全連合を実測（ただし推定誤差あり）」に改める。

**[C-03] 重大 — Shapley と solo の差が出にくい構造（A1 が差なしになる恐れ）**

- 改善案（v4）: 候補集団に「solo は弱いがチームで効く」タイプ（専門特化・反対意見型・検証特化）を意図的に含める。そのうえで、静的なチーム選抜研究で Shapley と solo の順位相関と、選抜後の held-out 性能差を先に測る。これを進化の前提条件の確認として位置づける。

```python
            if not m or m[0]["role"] != "system" or "ANSWER: <letter>" not in m[0]["content"]:
                continue
            resp = r.get("response") or ""
            n += 1; flip += old.extract_answer(resp, "letter") != new.extract_answer(resp, "letter")
    if n:
        print(f"{f.split('/')[-1]:32s} letter_calls={n:5d} flipped={flip:4d} ({100*flip/n:.1f}%)")
```
