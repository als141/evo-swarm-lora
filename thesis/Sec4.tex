\section{モデルと実行環境}
\label{sec:4.1}

\subsection{推論}
\label{sec:4.1.1}

ベースモデルは，指示調整済みの約40億パラメータのモデルQwen3-4B-Instruct-2507\cite{qwen2025qwen3}である．推論にはvLLM 0.8.5\cite{kwon2023efficient}のOpenAI互換サーバを用いる．ベースモデルをbf16で読み込み，複数のLoRA（最大12個，rank 16まで）を同時に載せ，個体ごとに切り替えて生成する．LoRAは実行中に動的に読み込む．

生成の設定は全条件・全ラウンドで共通とし，温度0.7，top-p 0.8，top-k 20，出力の上限8,192トークンとする（表\ref{tab:4.3}）．温度とtop-p，top-kの値はモデルの推奨設定に合わせた．各トークンの対数確率も取得し，発話の平均トークン対数確率を集約の同点処理（\ref{sec:3.3.4}項）の確信度に用いる．

出力の上限に達した生成は，その時点の出力のまま採点する．途中で打ち切る規則を設けると条件間で扱いが変わりうるため，上限は全条件で共通とした．例外として，同じ文字列が周期的に繰り返す完全な反復に陥った生成だけは，生成中に検出して打ち切る．具体的には，生成した400文字ごとに末尾を調べ，同じ文字列が5回以上かつ合計1,500文字以上続いていれば打ち切る．完全一致の周期性だけを見る保守的な判定であり，正常な推論文を誤って打ち切りにくい．

\subsection{学習}
\label{sec:4.1.2}

LoRAの学習には，peft 0.15.2とtransformers 4.51.3（PyTorch 2.6.0）を用いる．ベースモデルはbf16で読み込み，注意機構にはPyTorchのscaled dot-product attentionを，メモリの節約に勾配チェックポイントを用いる．学習と推論は同じジョブの中で交互に行い，学習の間は推論サーバを止めてGPUを学習に充てる．

\subsection{実行環境の固定と非決定性}
\label{sec:4.1.3}

すべての実験は，vLLM 0.8.5の公式イメージに学習用のパッケージを加えた一つのコンテナイメージで行う．イメージはダイジェスト（\texttt{sha256:41ab7010...}）で指定し，実験期間中は作り直さない．推論経路のパッケージの版は制約ファイルで固定し，追加のインストールがそれらを変えるとビルドが失敗するようにした．コードはイメージに含めず，各ジョブが起動時にクラウドストレージからコードの版ごとのスナップショットを取得する．予備研究では，実験の途中で環境を作り直したため，測定値の差が環境によるものかどうかを切り分けられなかった（第\ref{cha:5}章）．環境を一つに固定することで，この種の交絡を排除する．

vLLMの生成は，同じseedを指定しても出力が再現しない（予備研究で確認した．第\ref{cha:5}章）．GPU上の浮動小数点演算は結合的でなく，計算の順序によって結果が変わるためである\cite{cooper2026nondeterminism}．そこで，すべての呼び出しを（ラウンド，エージェント，相手の集合，問題，生成seed）からなる一意のキーで一度だけ生成して保存し，再生成しない．採点と統計は保存した出力に対してオフラインで行うため，生成は再現しなくても分析は再現できる．

\section{ベンチマークと問題集合}
\label{sec:4.2}

\subsection{ベンチマーク}
\label{sec:4.2.1}

性質の異なる3つのベンチマークを用いる．
\begin{itemize}
\item \textbf{MMLU-Pro}\cite{wang2024mmlupro}: 多分野の知識と推論を問う多肢選択問題．選択肢は最大10個（A〜J）である．
\item \textbf{SuperGPQA}\cite{du2025supergpqa}: 大学院水準の専門知識を問う多分野の多肢選択問題．選択肢は最大10個である．
\item \textbf{MATH}\cite{hendrycks2021measuring}: 競技数学の自由記述問題．難易度はLevel 1〜5に分かれる．評価には難度の高いLevel 4と5の問題だけを用いる．
\end{itemize}
多肢選択の問題は，問題文の後に「A. 選択肢」の形式で選択肢を並べて提示する．予備研究で精度がほぼ飽和していたGSM8K\cite{cobbe2021training}は用いない．

\textbf{test}は，予備研究で一度も使っていない問題から無作為に抽出した．testは最終評価だけに用い，選抜や設計の判断には一切用いない．適応的な調整に使ったデータで勝者を評価すると，そのスコアは過大になるためである\cite{xu2026siren}．

\textbf{dev}は，予備研究で使用済みの問題から，ベースモデルの正答率$p$に基づいて層化して抽出した．$p$は，予備研究で保存したベースモデルの生出力（1問あたり複数の標本）を，本研究の採点器（\ref{sec:4.3}節）で採点し直して求めた．各ベンチマークで，$0 < p < 1$の問題を70\%，$p = 1$の問題を30\%とし，$p = 0$の問題は含めない．$0 < p < 1$の問題は候補間の差を識別しやすい．$p = 1$の問題は，学習による能力の劣化（ベースモデルなら解ける問題を落とすこと）を検出するために含める．devにおける$p$の平均は，MMLU-Pro 0.638，SuperGPQA 0.666，MATH 0.853である．

devは，ベンチマークごとに層化して固定seedで半分ずつに分け，dev-Aとdev-Bとした．dev-Aとdev-Bは世代0の選定（\ref{sec:3.2}節）に，dev全体は進化の選抜に用いる．

\textbf{学習用の問題}$Q_0, \dots, Q_5$は，test，dev，予備研究で使用済みの問題のいずれとも重ならない．MMLU-Proはtest分割の残りから，SuperGPQAは残りの問題から，MATHはtrain分割のLevel 3〜5から抽出した．世代$t$の議論には$Q_{t-1}$を用い，同じ問題を二度学習に使わない．正解は，多肢選択では正解の選択肢の記号，MATHでは解答例の最後の\verb|\boxed{}|の中身（MATH-500では収録された正解）とした．

\section{採点}
\label{sec:4.3}

\subsection{回答の抽出と判定}
\label{sec:4.3.1}

正誤の判定は，生成文から回答を取り出す抽出と，取り出した回答を正解と照合する判定の2段からなる（\ref{sec:2.6}節）．システムプロンプトは，最終行に\texttt{ANSWER: <letter>}（MATHでは\texttt{ANSWER: <final simplified answer>}）の書式で答えるよう指示する．

\textbf{抽出}．生成文の最後の\texttt{ANSWER:}行を探し，同じ行にある文字列を捕捉する．同じ行が空なら，次の空でない行を用いる．多肢選択では，捕捉した文字列から次の順で選択肢の記号を取り出す．
\begin{enumerate}
\item 先頭にある記号（\texttt{H}，\texttt{**H**}，\texttt{(H)}，\verb|\boxed{H}|など）．
\item 「Option C」「answer is C」のようなキーワードに続く記号．
\item 独立した1文字のトークンとしての記号．複数ある場合は，一人称の「I」を除いた最後の記号．
\end{enumerate}
\texttt{ANSWER:}行がない場合は，本文全体から「the answer is X」「\verb|\boxed{X}|」「\texttt{**X**}」の形の最後の一致を用いる．MATHでは，\texttt{ANSWER:}行の内容（その中に\verb|\boxed{}|があればその中身）を取り出し，行がなければ本文の最後の\verb|\boxed{}|の中身を用いる．

\textbf{判定}．多肢選択は記号の一致で判定する．MATHは，まず表記を正規化して比較する．正規化では，\verb|\text{}|や\verb|\left|，空白，度やパーセントの記号，先頭の「$x=$」を除き，分数や根号を統一した形に直し，数値は数として比べる．一致しなければ，Math-Verify\cite{kydlicek2025mathverify}（0.8.0）による記号的な同値判定を用いる（1問あたり5秒で打ち切る）．testのMATH 300問の正解は，すべてMath-Verifyで解析できることを確認した．

回答を抽出できなかった出力は誤答として扱う．抽出できない出力の割合（None率）は条件ごとに第\ref{cha:5}章で報告し，条件間で大きく異ならないことを確かめる．

\subsection{予備研究の採点器の監査}
\label{sec:4.3.2}

本研究の採点器は，予備研究の採点器に見つかった次の3つの欠陥を直したものである．
\begin{enumerate}
\item \textbf{改行をまたぐ捕捉}: 旧実装は，\texttt{ANSWER:}の後の空白に改行を含めて捕捉していた．そのため，「Final Answer:」の次の行に「ANSWER: H」と書いた出力から，単語ANSWERの頭文字の「A」を回答として取り出していた．予備研究で保存したベースモデルの10択の呼び出し34,608件に新旧の抽出器を適用すると，9.1\%（3,142件）で結果が変わり，すべて旧が「A」だった．
\item \textbf{最初の文字の採用}: 旧実装は，捕捉した文字列に最初に現れるA〜Jの文字を回答としていた．そのため「ANSWER: Option C」を「I」と判定していた．
\item \textbf{数式の偽陰性}: 旧実装は，簡単な文字列の正規化だけで数式を比べていた．そのため\verb|\sqrt2|と\verb|\sqrt{2}|，\verb|\frac59|と\verb|\frac{5}{9}|，度の記号や「$x=$」の有無といった表記の違いを誤答としていた．予備研究のMATHの予測9,600件のうち，6.49\%（623件）が偽陰性だった．
\end{enumerate}

これらの欠陥は条件によって偏って効いていた．1番目の欠陥で結果が変わった呼び出しの割合は，ベースモデルとSCでは10.6〜16.8\%だったのに対し，出力の書式をSFTで揃えたLoRAのチームでは0.0〜0.1\%だった．採点器の誤りが条件によって偏れば，条件間の比較そのものが歪む．そこで本研究では，採点器を評価の前に固定し，保存した生出力に新旧の抽出器を適用して条件ごとに誤りを監査した．予備研究の結果を修正した採点器で採点し直した結果は，第\ref{cha:5}章で報告する．

\subsection{単一モデルの自己学習（RFT）}
\label{sec:4.4.2}

「社会の進化は，同じ問題で単に自己学習した場合に比べて何を加えるのか」を測る対照として，ペルソナも議論も用いない単一モデルの棄却サンプリング微調整（rejection sampling fine-tuning; RFT）\cite{zelikman2022star,yuan2023scaling}を置く．

ベースモデル（ペルソナ文なし）で，系統Sが3世代で用いる学習用の問題（$Q_0$〜$Q_2$の計3,600問）を1問あたり2回サンプリングする．生成が完了した正解の出力を1問につき1例まで集め，上限を3,000例とする．この上限は，1体のペルソナが3世代の学習で使う例数の上限（1,000例$\times$3世代）に等しい．これで新しいLoRAを1エポック学習する（学習率$1 \times 10^{-4}$，他の設定は系統と同じ）．学習したモデルでtestの各問題を9回サンプリングし，単独の精度とSC@$k$を求める．

\subsection{基準}
\label{sec:4.4.3}

\begin{itemize}
\item \textbf{ベースモデル単体}: ペルソナ文なしでtestの各問題を9回サンプリング（生成seed 1）し，その平均正答率を単独の精度とする．これは1回の生成の期待精度である．
\item \textbf{SC@$k$}（$k = 1, \dots, 9$）\cite{wang2023selfconsistency}: 同じ9本の標本のうち最初の$k$本の多数決．同数の処理は\ref{sec:3.3.4}項と同じである．副次的なSC@$k$の曲線（\ref{sec:4.5.3}項）では，9本から$k$本を選ぶ全組合せでの正答率の平均（期待値）を用い，標本の順序による揺らぎを除く．
\item \textbf{世代0の社会}: 採用したトリオ（LoRAなし）を，系統と同じプロトコルとゲーティングで評価する．主要比較H1（\ref{sec:4.5}節）の基準である．
\item \textbf{7月のチーム}: 予備研究で最良だったチーム（ベースモデル自身の正解を混ぜたSFTで学習したLoRAと，日本語のペルソナ文）を，本研究のtestで評価する．議論は予備研究の手続き（自分の前回の回答を提示せず，匿名化した他者の回答と条件付きの指示を一つのuserの発話で与える）を本環境で再実装したもので，ゲーティングは行わない．集約は本研究の規則（\ref{sec:3.3.4}項）に揃える．予備研究の手法の位置を，修正した採点器と新しいtestで確かめるための条件である．
\end{itemize}

\subsection{生成の回数と出力トークン数の考慮}
\label{sec:4.4.4}

議論のチームは，1問あたりround0で3回，round1で最大3回，合わせて最大6回の生成を行い，ゲーティングの下ではそれより少ない．議論はこれと同程度の生成回数のSelf-Consistencyと比べるべきだという批判がある\cite{smit2024should}．そこで，最終世代の社会とSC@$k$を，1問あたりの生成回数と出力トークン数をそろえた点で比べる（RQ4）．round1は他者の回答を入力に含むため入力トークンが多く，この点はSCに有利な比較となる．入力トークン数も併せて報告する．

\section{評価指標と統計}
\label{sec:4.5}

\subsection{評価指標}
\label{sec:4.5.1}

主要な評価指標は，testのベンチマーク等重み（macro）の精度
\begin{equation}
\mathrm{Acc}_{\mathrm{macro}} = \frac{1}{K} \sum_{k=1}^{K} \frac{1}{n_k} \sum_{i \in I_k} s_i
\label{eq:macroacc}
\end{equation}
である．ここで$I_k$はベンチマーク$k$の問題の集合，$n_k = |I_k|$，$s_i \in [0, 1]$は問題$i$の得点（生成seedが複数あればその平均正答）である．副次的な指標として，問題数で重み付けした精度（micro）とベンチマーク別の精度を報告する．

\subsection{主要な比較と検定}
\label{sec:4.5.2}

主要な比較は次の3つであり，結果を見る前に定めた．
\begin{itemize}
\item \textbf{H1}（RQ1，進化の効果）: 系統Sの最終世代の社会の精度は，世代0の社会より高い．
\item \textbf{H2}（RQ2，選抜の効果）: 系統Sの最終世代の精度は，系統Nの最終世代より高い．
\item \textbf{H3}（RQ3，適応度の水準）: 系統Sの最終世代の精度は，系統A1の最終世代より高い．
\end{itemize}
3つの検定の族について，Holmの方法\cite{holm1979simple}で族全体の第1種の誤りの確率を5\%に抑える．

検定は，問題を単位とする対応のある比較である\cite{miller2024adding}．2条件の問題ごとの得点の差を$d_i$とし，検定統計量をベンチマーク内の平均差の等重み平均
\begin{equation}
\Delta = \frac{1}{K} \sum_{k=1}^{K} \frac{1}{n_k} \sum_{i \in I_k} d_i
\label{eq:delta}
\end{equation}
とする．$p$値は，問題ごとに差の符号を無作為に反転させる符号反転の並べ替え検定（両側，20,000回）で求める．反転後の統計量$\Delta^{(b)}$から，$p = (1 + \#\{b : |\Delta^{(b)}| \geq |\Delta|\}) / (B + 1)$とする（$B = 20{,}000$）．信頼区間は，ベンチマーク内で問題を復元抽出するブートストラップ（10,000回）のパーセンタイル区間とする．生成seedが複数ある場合は，問題ごとに平均してから比べるので，問題が検定の単位（クラスタ）になる．比較には，両条件の結果がそろった問題だけを用いる．

主要比較のチーム（世代0と各系統の最終世代）は，testを生成seed 2本で評価し，問題ごとに2本の平均を得点とする．途中の世代は生成seed 1本で評価する．事前登録からの逸脱があれば，その理由を第\ref{cha:5}章で報告する．同等性を主張する場合は，事前に定めたマージン$\pm 2$ptを用い，差の90\%信頼区間がこの範囲に収まるときに限る．

\subsection{副次的な分析}
\label{sec:4.5.3}

次の分析は探索的なものであり，多重性の補正は行わず，信頼区間とともに報告する．
\begin{itemize}
\item 系統Sの世代ごとの精度の推移．
\item SC@$k$の曲線に対する各手法の位置（生成回数と出力トークン数をそろえた比較）．
\item 議論における正誤の遷移（round0で少数派の正解が多数派に合わせた割合，多数派が答えを維持した割合など）．
\item ペルソナ間の回答の多様性（不一致率と，3体のうち少なくとも1体が正解する割合oracle@3）の世代ごとの推移．
\item 候補のShapley値と単独の精度の順位相関，およびShapley値とBanzhaf値の順位の一致．
\end{itemize}

\subsection{事前登録からの変更}
\label{sec:4.6.3}

設計の文書を固定した後に行った変更を，日時と理由とともに次に示す．いずれもdevでの結果と計算量の実測だけに基づいて行い，testの結果は判断に用いていない．
\begin{enumerate}
\item \textbf{コンテキスト長の上限の拡張}（2026年9月30日）: 全員が迷走した問題では，round1の入力が約2.5万トークンになり，出力の上限8,192トークンと合わせてvLLMの上限32,768トークンを超えた．上限を49,152トークンに拡張した．生成の内容は変わらない．
\item \textbf{出力の上限の維持}（同日）: 上限8,192トークンに達した出力は完全な反復ではなかった．途中で切ると条件間で扱いが変わりうるため，上限は全条件で共通のまま維持し，完全反復の打ち切りだけを残した．
\item \textbf{round1の採用候補の変更}（同日，第2パイロットの前）: 計算量の制約から，採用候補を切り詰め版の2種に改め，全文版は参照とした（\ref{sec:4.6.2}項）．
\item \textbf{ゲーティングの導入}（同日，本実験の前）: dev-Aでの比較に基づき，進化と評価に導入した（\ref{sec:4.6.2}項）．
\item \textbf{対照系統の評価の縮小}（同日，本実験の前）: 費用を抑えるため，系統NとA1のtestの評価を最終世代だけとした．主要比較H2とH3は最終世代同士の比較なので，この変更の影響を受けない．
\item \textbf{社会学習のデータの構成}（同日，本実験の前）: 当初は，子bのデータを「aの例と他者の正解例を合わせた中から1,000例を無作為に抽出」としていた．しかし1,200問の議論からは自己学習の例が約2,000例得られるのに対し，他者の例は数百例にとどまる．無作為に抽出すると他者の例の約半分が落ち，bがaとほとんど同じになる．aとbの違いを社会学習の成分として保つため，他者の例をすべて含め，残りを自己学習の例で補う構成に改めた（\ref{sec:3.5.2}項）．
\end{enumerate}
